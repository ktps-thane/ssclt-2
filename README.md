# ssclt-2 · ระบบจัดรถ SSC (แบบร่าง V1)

แอปจัดรถและบริหารรถบรรทุกของ บริษัท ภูเก็ตศรีสุชาติขนส่ง จำกัด ทำตามเอกสาร
"สรุปภาพรวมโครงการระบบจัดรถและบริหารรถบรรทุก SSC — Version 1"

ลิงก์ใช้งาน: https://claude.ai/artifact/T88htFkDJQh7B4LPZUe5Vd
ลิงก์สำหรับคนขับ (หน้าเช็คอิน): https://claude.ai/artifact/T88htFkDJQh7B4LPZUe5Vd#checkin

## มีอะไรบ้างในแบบร่างนี้

| หน้า | ทำอะไร | อ้างอิงเอกสาร |
|---|---|---|
| ภาพรวม | ขั้นตอนจัดรถวันนี้, เรื่องที่ต้องดูแล, สรุปเดือน (Trip/Job, KM, น้ำมัน, ต้นทุน, รายได้), Southern Load Planning, Loaded/Empty KM, คนขับ, Maintenance | ข้อ 20 |
| คิวรถ / เช็คอินคนขับ | คนขับเช็คอินพร้อมพิกัด (GPS หรือวางจาก Google Maps), ตรวจรัศมีจากคลัง, เลขคิวตามเวลาที่มาถึง | ใหม่ |
| ออเดอร์ | เพิ่ม/นำเข้าออเดอร์ (วางจาก Excel), ประเภทงาน FH/BH/ภาคใต้, ข้อมูลที่ Checker ใช้ | ข้อ 3, 6, 7 |
| จัดรถ | Order → Route → Vehicle Matching → Maintenance Check → Dispatch, ตรวจความจุ รายได้ขั้นต่ำ (อนุมัติพิเศษ) และประเภทรถตาม Checker | ข้อ 7, 8, 9, 19 |
| ทริป | 1 Trip หลาย Job, ออกรถ/ปิดทริป, เลขไมล์, Standard/Actual/Variance, Loaded/Empty KM, น้ำมัน Feed Card, เบี้ยเลี้ยง, ทางด่วน, ส่วนแบ่ง Partner | ข้อ 5, 10–15 |
| Maintenance | Current/Last/Next/Remaining KM รอบ 20,000 กม., บันทึกเข้าศูนย์ | ข้อ 18, 19 |
| ข้อมูลหลัก | รถ (ทะเบียนหางเป็น ID หลัก), คนขับ, จุดเช็คอิน (ปักหมุด + ชื่อเรียกหน้างาน), เส้นทาง | ข้อ 16, 24 |
| หางสำรอง | เบิก/คืนหาง พร้อม KM และคนขับ | ข้อ 17 |
| ค่าตั้งค่า | น้ำมันมาตรฐาน, Minimum Release Revenue, ส่วนแบ่ง Partner, เกณฑ์เตือน | ข้อ 8, 10, 14, 18 |
| ร่างระบบเช็คอิน / รอข้อมูล | สเปกร่าง กฎคิว รายการไฟล์ที่รอ และคำถามที่ต้องยืนยัน | ข้อ 24 |

ข้อมูลจริงยังไม่มีรถและคนขับ (รอไฟล์) จึงเปิดเป็น **โหมดทดลอง** อัตโนมัติด้วยข้อมูลสมมติ
ที่เก็บในเครื่องผู้ใช้เท่านั้น กด "ใช้ข้อมูลจริง" เพื่อสลับ ข้อมูลจริงตอนนี้มีจุดเช็คอิน 2 จุด
และรายชื่อเส้นทางจากเอกสาร V1 (ยังไม่มี Standard KM)

## โครงสร้าง

- `app/index.html` หน้าเดียวทั้งแอป (HTML/CSS/JS ล้วน ไม่มี build) เผยแพร่เป็น Claude Artifact
  ที่ใช้ความสามารถ `db` (ฐานข้อมูลที่ทุกคนที่เปิดลิงก์เห็นร่วมกัน) และ `user`
  ไฟล์นี้ไม่มี `<!doctype>`/`<head>` เพราะตอนเผยแพร่ระบบจะครอบให้
  ถ้าเปิดไฟล์ตรงๆ นอก Claude ข้อมูลจะเก็บใน localStorage ของเครื่องนั้น
- คอลเลกชันในฐานข้อมูล: `vehicles`, `drivers`, `sites`, `routes`, `orders`, `trips`
  (มี `jobs` อยู่ข้างใน), `checkins`, `trailers`, `config/settings`
- `tests/` สคริปต์ Playwright ที่ใช้ทดสอบก่อนส่งงาน

## ทดสอบ

```sh
sh tests/wrap.sh app/index.html /tmp/page.html
mkdir -p /tmp/shots
node tests/app-flows.test.js /tmp/shots /tmp/page.html     # ทุกหน้า + ขั้นตอนหลัก (โหมดทดลอง)
node tests/shared-data.test.js /tmp/shots /tmp/page.html   # โหมดข้อมูลจริง 2 แท็บ (คนขับ + ฝ่ายจัดรถ)
```

## ข้อจำกัดของแบบร่าง

- ในหน้าต่าง Claude เบราว์เซอร์อาจไม่ให้อ่าน GPS จึงมีวิธีวางพิกัดจาก Google Maps เป็นทางสำรอง
- เวลาเช็คอินใช้นาฬิกาของมือถือ ระบบจริงควรใช้เวลาจากเซิร์ฟเวอร์
- คนขับต้องได้รับสิทธิ์เปิดลิงก์ (Contributor) จากเจ้าของจึงจะบันทึกได้
